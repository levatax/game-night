# Contract changes

Append-only log of contract deviations / additions (one line each, prefixed with the role).

- server-room: CreateOptions gains a test-only `warp?: number` (1..8, read as unknown; honored only with RAFT_TEST=1 + fast: true): the room simulates `warp` ticks per real 1/30 s so bot-only test matches finish sooner (server/room/testing.ts). Real clients never send it.
- server-room: StartMsg semantics: the host's Start counts as the host's own ready (every OTHER human must be ready; bots are always ready) — the lobby UI doesn't need to make the host press Ready first.
- server-world-life: FishingSystem.use() emits its own `reject` (action "fish", reason "noSpot" when no spot is in view, "busy" when swimming) before returning false — RaftWorld must not emit a second reject for a false return.
- server-world-life: MonsterSystem credits kills itself (flip / pop / boss kill, incl. blasts: byId's stats.kills++ and MVP_POINTS.kill); RaftWorld keeps crediting hits (stats.hits, MVP_POINTS.hit) as projectiles.ts already does — no double counting either way.
- server-world-life: monsters break fences themselves (StructureState.hp −1 per FENCE_GNAW_TICKS/FENCE_HP of crab gnawing, the boss smashes, a snagged puffer pops for −1): state.structures.delete + structureHit / structureDestroyed (byId = monster id) + ctx.cover.setStructures(); RaftWorld's structure code must tolerate a fence vanishing between its steps.
- server-world-life: puffer damage is deduplicated per monster per tick between hitByProjectile(puffer projectile → returns "consume") and blast(), so RaftWorld may call either or both for a puffer impact.
- server-world-life: onClock() may be called every tick or only on transitions — MonsterSystem / WeatherSystem also derive the clock from state.clockTicks in step() (phase "playing") and fire each dawn / dusk / night / mid-day / event-time transition once per day (a clock that runs backwards = new match, marks reset).
- server-world-life: added (optional) exports — MonsterSystem.spawnMonster(kind, x, z, opts) (dev harness / tests), wavePlan(team), queued(); FishingSystem.biteWindowTicks(p), lootTable(); WeatherSystem.onPickup(p, projectileId) (exact wave-gift treasure attribution; without it a vanished gift item is credited to the nearest player within PICKUP_RANGE + 1.2 m) and forecast(). The wave-gift treasure reel runs on WeatherSystem's own TreasureReels (it holds no FishingSystem); FishingSystem.treasureReel still serves the secret chest.
- server-world-life: the fishing lag allowance falls back to PlayerState.ping when setRtt() was never called; FishBiteEvent.windowTicks is the visible FISH_BITE_TICKS (the RTT/2 allowance is server-side slack only).
- server-world: shared/rules/interact.ts `InteractWorld.state` gains an optional `fast?: boolean` (RAFT_TEST one-of-everything raft costs for the deliver prompt); a full RaftStateView already satisfies it, so callers passing `{ island, state }` need no change. New exports there for HUD / bots: INTERACT_PRIORITY, interactRank, planRaftDelivery (the exact plan the server executes), planWood, raftRemaining, raftStageFor, raftPartValue, teamRaftCost, raftWantedItem, carriesRaftGoods, FOOD_DELIVERY_ORDER, resetInteraction.
- server-world: resolveInteraction ranks ok candidates before greyed-out ones (then kind priority, then view angle), so a full-pockets pickup never hides a tree you can chop; `craft` is always ok (the panel can feed a dead fire) with reason "fireOut" as a hint while the fire is out.
- server-world: RaftWorld calls monsters.onClock / weather.onClock on EVERY playing tick with (previous tick's clock, this tick's clock); the systems detect their own transitions. RaftWorld.rng / RaftWorld.tick are bound function properties (safe to pass around detached, as the life systems do).
- server-world: Q tosses spawn "loose" projectiles (harmless, catchable, still burn as fuel / bait / explode as puffers); only charged LMB throws are "live". RaftWorld calls weather.onPickup(p, projectileId) on every ground pickup (E). Reject reasons used beyond §7's list semantics: "full" also for feeding an already-full fire and for the spring with full pockets + full thirst, "dead" for craft / chest while downed.
- island: defHash (shared/island/generate.ts, used for WelcomeMsg.defHash) now also covers layout, biome, grid size, every site field (center, wreck, all spawns, campfire, chest, raft, spring, cave, secret chest, every shore cell), node collider radius / height / island and fish-spot island — a superset of the fields listed in island/types.ts IslandDef.defHash JSDoc. Server and client call the same function, so nobody else changes anything; cosmetic node yaw / variant stay out of it.
